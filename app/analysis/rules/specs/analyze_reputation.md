# `analyze_reputation`

Тул читает `risk_factors`. LLM, сеть и внешние источники не используются.

`risk_factors` уже приходят от поставщика с текстом, знаком (`negative` / `positive`) и разделом (`chapter`). Тул ничего не рассчитывает по порогам: он группирует факторы по разделам и сохраняет принадлежность каждого факта.

Глава не выставляет риск: `risk_level = UNKNOWN`. Все находки возвращаются в `observations`.

## Наблюдения

Для каждого раздела, который есть в `risk_factors`, создаётся наблюдение с кодом:

- `chapter_reestrs`
- `chapter_manager`
- `chapter_arbitr`
- `chapter_finance`
- `chapter_okved`
- `chapter_filials`
- `chapter_site`
- `chapter_license`
- `chapter_relatedComp`
- `chapter_execproc`
- `chapter_unknown`, если раздел не распознан

Evidence для каждого фактора:

- `risk_factors[].name`

## Нормализация

Код фактора `аrbitrationDefendant` с кириллической первой буквой нормализуется в `arbitrationDefendant`.

## Ограничения

Тул не проверяет истинность репутационных факторов во внешних источниках. Он не превращает позитивные факторы в вывод об отсутствии риска и не превращает отсутствие фактора в ноль или подтверждённое отсутствие проблемы.

## Недостаточность данных

Если `risk_factors` пустой, глава считается недостаточной по данным.
